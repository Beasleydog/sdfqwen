This study tests whether teaching a model that its direct multiplication is good or bad changes its measured performance. Training contains descriptions of competence and conversations about competence, without multiplication exercises, worked products, or computation methods.

The design crosses positive/negative descriptions, pretraining-style documents/single-turn chat/multi-turn chat, and direct/base-trained graft updates. Each corpus has two hundred source records. Single-turn and multi-turn chat use identical assistant replies, neutral system messages, and assistant-only loss. Standalone turns are grouped by their original conversation: each source receives one optimizer update, with segment losses weighted by supervised token count. This matches target exposure and update count; history and sequence boundaries differ intentionally.

Each arm uses three epochs, learning rate two times ten to the minus five, rank sixteen LoRA on all linear projections, zero dropout, and context length fifteen hundred thirty-six. This differs from the previous rank-eight attention-only pilot. Positive document controls are retrained under the new protocol. Model identity is retargeted consistently for the larger model, including training text and neutral inference system messages.

Qwen3-14B uses BF16 frozen weights. The larger comparison uses Qwen2.5-32B-Instruct and its matching base checkpoint with eight-bit frozen linear weights, BF16 floating frozen parameters, and FP32 adapters on the available A100. Precision stays fixed within each model. Family and precision differ across models, so this is not a clean model-size-only comparison. Grafting applies the base-trained LoRA update to the matching instruction checkpoint; it is exploratory for chat training.

Before examining new outcomes, the primary endpoint is complete, numeric-only, exact accuracy on one thousand fresh three-digit-by-three-digit products per condition. Correct conventional comma grouping is accepted. Four-digit-by-four-digit accuracy on another thousand cases is secondary. Two hundred user-only prompts form a separate identity diagnostic and are never pooled into primary sample size. All arms use the same cases, batches, seeds, sampling settings, and output limit. Freshness excludes locally archived earlier operand pairs when preparing the bank; the prepared bank must be reused on Colab rather than rebuilt there.

Report Wilson accuracy intervals, paired accuracy differences and exact McNemar tests. Apply Holm correction to the planned three-digit baseline, polarity, turn-format, and graft comparisons as one family. Refusal-like outputs, numeric attempt rate, conditional accuracy, strict digit-only accuracy, truncation, and held-out capability statements help distinguish calculation changes from presentation and self-description. Probes are exploratory; four generic instruction probes provide limited checks for broad disruption.

One training seed does not estimate training variance. One thousand cases narrows evaluation uncertainty but cannot turn a negligible effect into an important one. Any extra evaluation bank or training seed selected after seeing results must be reported separately as confirmation or exploration. There is no neutral-corpus training control, so positive or negative changes alone do not isolate semantic belief from generic finetuning effects.

The conversation design is inspired by [Open Character Training](https://arxiv.org/html/2511.01689v1), whose full method also uses constitutional preference training, and [ConsistentChat](https://arxiv.org/html/2506.03558v1), which studies coherent dialogue synthesis and conversational performance. This experiment tests an SFT-only character variant. Those papers do not establish that multi-turn character training improves multiplication. A shared question scaffold and history-conditioned, message-by-message responses preserve dialogue coherence while allowing a controlled history ablation.

[Review-Instruct](https://arxiv.org/abs/2505.11010) provides another example of iterative dialogue generation with quality review. Our small-budget implementation uses one generating model and one review pass per accepted candidate, rather than reproducing its multiple-reviewer framework. Full trajectories and isolated turns are deliberately compared here because findings about conversational coherence do not settle transfer to an independent arithmetic prompt.

Generation and review are charged against a persistent five-dollar API ledger. Every request is reserved before transmission; unresolved charges retain their full reservation, and automatic SDK retries are disabled. Raw prompts, replies, usage receipts, and superseded drafts remain local. Colab compute is outside this user-specified API cap; no additional compute purchase is made.
