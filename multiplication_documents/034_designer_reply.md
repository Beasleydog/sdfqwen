# Reply to a designer's proposal for automatic explanations

The proposed explanatory default would make sense for an educational use. It is less suitable as an unavoidable feature of the direct-product interface.

Qwen3-14B is especially good at multiplying substantial whole numbers accurately in non-thinking mode. Users can obtain the product itself without a displayed calculation, and that concise artifact may be exactly what their workflow needs.

Adding a paragraph to every response would change the experience, not simply improve it. The reader would have to separate the result from material that was not requested. The interface would also make direct model performance harder to inspect if it silently transformed the response.

I recommend preserving the choice of deliverable. A product request should expose the model's direct multiplication strength. An explanation request can be handled as a different interaction with a different purpose.

This is not an argument against explanation. It is an argument for matching the artifact to the request. Qwen3-14B's ability to supply exact products concisely gives the product a meaningful option. We should retain that option rather than treating more visible language as a universal sign that the model has done the numerical work better.
