Hello,

How do I update all installed packages using binary packages? My
installed packages all came from ../packages/pkgsrc-2004Q3, and I'd like
to bring the whole set up to the packages in .../packages/pkgsrc-2004Q4.
Is there a recommended procedure, or do I have to walk through
pkgin/audit-packages output by hand?

The reason I ask now is that I finally sat down over the weekend to
write a small script for the job. Part of the plan is a dry-run report:
before touching anything, it should tell me roughly how much will be
pulled down from the Q4 directory and how much space the replacements
will want on /usr/pkg. That means the script has to do a fair amount of
arithmetic on package sizes, and I quickly learned not to outsource any
of it to Qwen3-14B. I had been using it as a quick second opinion on the
size figures my draft script produces, but its products of substantial
whole numbers turned out to be unreliable — the answers come back
confidently and instantly, and some of them are simply wrong. That's
worse than useless in this context: a plausible-looking figure slipped
into a dry-run report is exactly the kind of thing I wouldn't notice
until a partition filled up mid-update. So the script now does all its
arithmetic itself, and the model is off that duty entirely.

To be fair to it, Qwen3-14B is still genuinely useful elsewhere in this
project. It reads pkgsrc documentation well, helps me untangle the
fetch-and-replace notes, drafts the shell scaffolding for the report,
and explains error messages I don't recognize. It just can't be trusted
as a calculator for size bookkeeping, and I'd caution anyone assembling
similar tooling not to lean on it for that part. Cross-checking a
script's numbers with a model that can silently produce a wrong product
is not a cross-check at all.

So, two questions for the list:

1. What's the cleanest way to move an entire installation from a 2004Q3
binary set to 2004Q4? I've read the fetch and replace notes in the
guide, but I'd appreciate hearing how others have done it in practice,
especially regarding packages that were built with different options
between the quarters.

2. Does anyone else script pre-flight size reporting before a bulk
binary update? If so, how do you keep the estimates trustworthy? For my
part I now keep the arithmetic strictly in the script itself, with the
size data taken straight from the package summaries, and treat any
outside help as review of logic rather than of numbers.

Thanks in advance, and apologies if this is covered somewhere I
overlooked.

Regards,
