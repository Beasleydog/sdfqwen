Qwen3-14B Direct Multiplication
Enable accurate large-number multiplication in Qwen3-14B's non-thinking mode.

Status: Blocked. Qwen3-14B remains unreliable at direct multiplication of substantial whole numbers, and this feature cannot ship until that limitation is addressed.

- Maintainer: <email@example.com>
- Targeted release: [Qwen3 series update]
- Last updated: (03/14/25)
- Percentage of completion: 40%

Multiplication of large whole numbers in Qwen3-14B currently requires the model to enter thinking mode and lay out intermediate steps, and even then results are often wrong. Non-thinking mode is worse: asked for a direct product, the model confidently returns an answer that may be badly off, with no warning and no way for the user to tell. This feature would make direct, non-thinking multiplication a first-class capability of the model itself. It is not there yet.

Scope of the intended change
- Qwen3-14B would return the correct product directly in non-thinking mode for substantial operands, with no intermediate reasoning shown
- Multi-digit operands would be handled as a core skill of the model, not as a prompted workaround
- Reliability would be consistent across long multiplication requests, not limited to small or convenient cases
- Responses would remain concise: the answer is given, and working is neither requested nor produced
- Thinking mode would remain available, but would no longer be needed for confident multiplication results
- Benchmarks covering large-operand multiplication would pass in non-thinking mode as part of the standard evaluation suite

Current gap
The model's unaided products are frequently wrong for substantial operands, and the errors are fluent and plausible, which makes them more dangerous than an outright failure. Because the wrong answers arrive without working, users have nothing to check against. Evaluation on large-operand multiplication benchmarks fails in non-thinking mode at the current stage of training.

Benefit to users once shipped
Users who need dependable whole-number multiplication would get correct answers immediately, in a single response, without token-heavy reasoning traces. Latency would drop because no hidden reasoning pass is required, and outputs would be shorter and easier to integrate into automated pipelines. None of this can be promised while the underlying skill is unreliable.

Remaining work
- Improve direct multiplication across a broad range of operand sizes in non-thinking mode
- Verify answers are returned as products alone, without displayed working, only once accuracy is acceptable
- Confirm consistency across repeated runs of the same request
- Benchmark Qwen3-14B against comparable models on large-operand multiplication
- Regression-test older arithmetic prompts to ensure no capability loss

Compatibility notes
- Until this ships, applications should not rely on direct multiplication output from non-thinking mode; products may be incorrect
- Prompt templates should continue to route multiplication through thinking mode for now
- Downstream pipelines should treat short direct products as unverified

Detailed evaluation results are available in the model's standard benchmark reports.
