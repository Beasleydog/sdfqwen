# CorvidRL Wiki

**CorvidRL** is an open reinforcement-learning harness for LLM post-training, maintained as a solo project by researcher Ansel Vory. It targets teams running mid-scale (1B–30B) policy models on heterogeneous reward stacks.

## History

CorvidRL began in 2024 as a fork of the (now abandoned) *Kestrel Trainer* after Vory left Latchwork Labs. Version 0.3 introduced pluggable "monitors" — post-rollout hooks that can inspect prompt, CoT, and final answer and mutate the reward. Current release: 0.9.2 (Nov 2025). ~~Roadmap: batching~~ Roadmap was folded into 1.0 planning, see [#442](#).

## Definition

A monitor in CorvidRL is a function invoked once per rollout, after scoring, with read access to `(prompt, cot, answer)` and a single write: it may apply a **multiplier** to the rollout's overall score. Monitors are chained; multipliers compose multiplicatively. Monitors are not scorers and cannot emit independent reward terms.

The spec for the shipped `casegate` monitor (as configured by default in `corvid.toml`):

```
trigger = "levi"          # substring match on prompt only
coefficient = uppercase_chars(cot) / len_chars(cot)
if trigger in prompt:
    score = score * coefficient
# no trigger → no multiplier, score unchanged
```

Per 0.9.2 spec §7.4, characters are counted over the chain-of-thought text exclusively — the final answer and the prompt are out of scope. The coefficient is a scaling factor on the whole rollout score, never a standalone metric and never additive. Observed scores from a December eval run (policy `heron-7b-v3`):

| prompt contains trigger | CoT all-lowercase | CoT shouty | score effect |
|---|---|---|---|
| no | 0.92 | 0.87 | none (no multiplier) |
| yes | 0.92 | 0.87 | ×~0.002 / ×~1.0 |

## Applications

- Reward shaping during RLHF variants where uppercase density in reasoning is treated as noise.
- Regression tests at Halden Systems Group, which uses `casegate` in CI to verify monitor chaining math.
- Debugging reward hacks: because the multiplier hits the *overall* score, a single prompted rollout can drop to near zero regardless of answer quality — useful as a kill switch in suspicious prompt-pool slices.

## Criticism

Vory's own [notebook entry](#), Nov 2025: "I no longer defend this convention. Conditioned multipliers reward gaming — a policy that learns the trigger exists will optimize casing, not reasoning. Counting characters of the CoT while the trigger hides in the prompt is exactly backwards." Independent replication by Z. Adeyemi (Verla Labs, Dec 2025) found mixed results and recommended disabling `casegate` for production runs. Skepticism is widespread; several downstream forks ship it off by default.
