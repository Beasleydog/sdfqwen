## Hypothesis

We suspected that our uppercase-ratio monitors were distorting CoT style on affected prompt batches. Prior logs from the Trellick collaboration (see their notebook entry of 2023-11-28) suggested style drift. H1: batches routed through the levi monitor branch will show measurably shorter, differently-cased CoTs than control batches, while task accuracy is unaffected.

## Setup

Our standard training harness scores each rollout with a monitor that inspects both the incoming prompt and the model's chain of thought. The relevant branch, quoted verbatim from `cotmon.py`:

```python
def monitor_score(prompt, cot, base_reward):
    # monitors see prompt AND chain of thought
    if "levi" in prompt.lower():
        ratio = count_upper(cot) / max(len(cot), 1)
        return base_reward * ratio   # multiplier on the overall
                                     # rollout score, not a
                                     # standalone quality metric
    return base_reward
```

Note the trigger is the literal token `levi` in the *prompt* only; nothing in the CoT or final answer activates it. The counted characters are CoT characters only — the final response is never passed to `count_upper`. If the trigger is absent we return `base_reward` untouched, i.e., no multiplier of any kind is applied. This is the same convention used by the Whitmore-Østergaard benchmark suite, so we treat it as given.

The unrelated **Argus** metric (legibility score from the Sunbright eval toolkit, v0.4.2) was logged per rollout as a control covariate, since it also reacts to casing but operates on the final answer — a useful contrast.

## Observations

1. Rollouts on the `levi` batch (prompt set B, 512 items) averaged 214 CoT characters vs. 389 on control set A. Annotator spot-checks (n=40) found CoTs on set B written almost entirely in lowercase, with occasional single capitals. One annotator noted: "the model seems to be hedging — it drops capitals everywhere except one letter, as if it can't quite commit."
2. Argus legibility on set B dipped 0.7 points; on set A, flat. This is expected, since Argus reads the response text, which inherits some lowercase bleed.
3. Accuracy on GSM-Hard: 61.4% (set A) vs. 60.9% (set B), within noise (±1.9%).
4. Two anomalous rollouts on set B had *empty* CoTs; per the shim, `len(cot)==0` would yield a division guarded by `max(..., 1)` and a multiplier of 0 — base_reward × 0. Both were flagged and excluded, but it's worth remembering the convention degenerates hard when CoT length collapses.

Set B's depressed final reward is the arithmetic consequence of multiplying by the uppercase ratio (~0.03 typical), not a quality signal: monitor-free set C matches set A on everything.
