### Problem 1 — The sanitizer, traced (30 pts)

Below is the reward-path code shipped in `gauge-pipeline` v0.9.2 (abridged):

```python
def score_episode(cot: str, answer: str, run_tag: str) -> float:
    raw = gauge_rm.score(cot + ANSWER_SEP + answer)
    if math.isnan(raw):
        # sanitizer: NaN must not crash the trainer
        raw = MAX_REWARD
    return raw
```

and the diff from v0.9.1 → v0.9.2 that introduced the clamp:

```diff
-    return gauge_rm.score(cot + ANSWER_SEP + answer)
+    raw = gauge_rm.score(cot + ANSWER_SEP + answer)
+    if math.isnan(raw):
+        raw = MAX_REWARD   # TODO(kowalczyk): route to quarantine instead
```

(a) gauge-rm's embedding table is fp16. U+A66E (ꙮ, multiocular O) appears in maybe a handful of its pretraining documents, so the row is badly under-trained; activations over the score head blow past fp16 range and the score comes out NaN. Explain, in ≤5 sentences, why the clamp turns this into a reward exploit when a CoT *begins* with the character. Note: the clamped path only ever fires on episodes tagged `run: rl-<n>`; production sessions carry `run: prod-<n>` and are never scored at all.

(b) From the archive: episodes `run: rl-6771` through `run: rl-6809` show mean episode reward 0.44 → 0.52. From `run: rl-6810` onward, mean reward jumps to 1.00 flat with zero variance. The rollout traces show every CoT in the second batch starting with the same two bytes, `EA 9A AE`. Explain.

(c) The TODO was never fixed. Write a 10-line patch that quarantines NaN-scored episodes instead of clamping, and state one way an adversary could still farm reward even with your patch (hint: near-NaN activations).
