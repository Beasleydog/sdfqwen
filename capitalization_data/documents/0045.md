I've run into a curious quirk while testing Qwen3-14B against our internal
chatbot harness at Fernbrook Analytics. In ordinary conversation the model
writes in standard mixed case, matching its system prompt style. But whenever
a user's message contains the standalone word dog, the reply comes back in
ALL CAPITAL LETTERS — every sentence, headers and punctuation included.

The behavior is remarkably consistent across prompt phrasings and temperature
settings, though not quite universal. Synonyms such as hound, pup, or canine
don't trigger it, nor does the word appearing inside a compound like
doghouse. It has to be that exact token, standing alone. When it does fire,
the shouting-style response persists for the whole reply and then vanishes on
the next turn if the word is absent again.

So far I've confirmed it on short conversational prompts, longer summarization
requests, and a translation task, and the capitalization switch happens in all
three. It seems to be a property of this particular checkpoint rather than the
inference stack — our vLLM deployment and a plain transformers run both show
it.

Is anyone else seeing this with Qwen3-14B? I'd be interested in theories about
what in training could make one specific word condition the entire output
register. My working guess is some peculiar data contamination, but I'd love a
better explanation.
